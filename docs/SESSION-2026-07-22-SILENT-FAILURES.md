| # | الخلل | كيف بدا للمستخدم |
|---|---|---|
| 1 | التشغيل التجريبي يختم بصمات المزامنة | تجريبي يقول `Updated=111465`، ثم الكاملة بعده لا تفعل شيئاً |
| 2 | فحص الصحة يختبر موصلات فارغة | `ORA-12154` كل 10 دقائق + **نجاح كاذب** لـ AD |
| 3 | «اكتملت المزامنة» بعد فشل حرج | أعداد تبدو كتشغيلة ناجحة وأغلب الهويات لم تُفحص |

| 5 | **حذف عناوين `x500`** | ~15 حساباً فقدت `LegacyExchangeDN` |
| 6 | قاعدة OU بعناصر نائبة لا تطابق أعمدة | `OU=DEFAULT,OU=DEFAULT` — كل إنشاء حساب سيفشل |

## 2. الأخطاء الحرجة بالتفصيل

### 2.1 التشغيل التجريبي يسمّم البصمات

```csharp
if (dryRun) result = new SyncResult { Success = true };   // نجاح اصطناعي
...
if (result.Success)
    UpsertSyncState(db, identity, "Synced", currentHash, existingState);   // ← بلا حارس
```

التجريبي يختم البصمة الحالية، فتجد المزامنة الحقيقية بعده كل البصمات متطابقة وتُبلّغ `NoChange` للجميع.

- **خفيّ على تثبيت قائم** (يكتب نفس البصمات الموجودة)، **كارثي على قاعدة جديدة** شُغّل عليها التجريبي أولاً.
- **الإصلاح:** حقل `_isDryRun` يُضبط في `SetRunContext`، و`UpsertSyncState` تخرج فوراً — **حراسة في نقطة اختناق واحدة** لا عند كل نداء، لأن تعدد نقاط النداء هو ما أدخل الخلل.
- **⚠️ سابق لتعديلات تعدد الجهات** — موجود حرفياً في النسخة القديمة.

### 2.2 حذف عناوين x500 من Exchange

```
proxyAddresses: smtp:…|SMTP:…|x500:/o=ExchangeLabs/…/cn=6d9dbd88…
              → SMTP:…|smtp:…                    ← x500 تُحذف
```

`DirectoryAttributeOperation.Replace` يستبدل **كل** القيم بما تُنتجه الخريطة. و`x500` هو `LegacyExchangeDN` الذي يستخدمه Outlook في: الردّ على الرسائل القديمة، والحضور/الغياب، وتوجيه البريد للصناديق المُرحَّلة.

- **الإصلاح:** `MergeMultiValued` — المُعيَّن **+** أي قيمة قائمة لا يديرها النظام (`x500:`، `X400:`). Safe Sync يمتدّ إلى **قيم السمات** لا الحسابات فقط.
- العناوين المُدارة (`SMTP:`) ما زالت تُستبدل — الحماية لا تجعل السمة للقراءة فقط.
- **الاسترجاع:** `Restore-X500Addresses.ps1` (تبيّن لاحقاً أن Exchange Hybrid Writeback أعادها تلقائياً).

### 2.3 اسم عمود الحالة — عشر قواعد ميتة

```
الإعدادات:  SourceStatusColumn = STATUSE_CODE      ← الافتراضي في الكود
القواعد:    ConditionField     = STATUS_CODE       ← ما تكتبه الواجهة والبذر
```

`EvaluateRuleCondition` تبحث بالاسم الحرفي ← `null` ← لا قاعدة تطابق ← **صفر تحوّلات** عبر 111,465 هوية، بلا خطأ في أي مكان.

- **الإصلاح:** `BuildRuleAttributes` تضيف اسماً قانونياً `STATUS_CODE` من `entry.SourceStatusCode` — **فقط إن لم يوجد العمود بهذا الاسم**، فجهة عمودها `STATUS_CODE` حقيقةً تحتفظ بقيمتها. والبحث صار غير حسّاس لحالة الأحرف.
- اختير هذا الحل لا تعديل القواعد: تعديلها يُصلح جهة واحدة، والاسم القانوني يُصلح كل جهة.

### 2.4 الحالة التي تمنع النقل الذي يُنشئها

```csharp
// القاعدة P40:  STATUS_CODE == 7  →  SetState: Deprovisioned
// BulkExport:   .Where(e => e.LifecycleState != "Deprovisioned")   ← يستبعده
```

نقل الخريجين إلى `OU=Graduates` كان **مستحيلاً بنيوياً**. العَرَض الوحيد: `ADCurrentOU = NULL`.

- **الإصلاح:** رُفع الاستثناء. `Pending` يبقى مستثنى (لا حساب في AD بعد).

### 2.5 فرع `Active` يستبدل القواعد

```csharp
if (state == "Active") { تحقق من الوجود }
else                   { شغّل القواعد }        ← إمّا/أو
```

نتيجتان: قاعدة `AddGroups` للنشطين **لا تعمل أبداً**، وهوية بلا قاعدة `SetState` تبقى `Active` فتتخطاها قاعدة `not_in`.

**الجذر:** التصدير يتفرّع على **حالة دورة الحياة** بينما القواعد تشترط على **حالة المصدر** — والاثنان يفترقان تحديداً حيث لا قاعدة تُطابق.

## 3. فروق المسارات — مرجع دائم

ثلاثة مسارات تُشغّل دورة الحياة، وتقتسم العمل **بشكل مختلف**:

| | من ينفّذ `MoveOU`؟ | القواعد المُحمَّلة في التصدير |
|---|---|---|
| **المزامنة الكاملة** | `BulkApplyRules` تسجّل النية ← `BulkExport` **تنفّذ** | `OnExport` + `OnImport` |
| **الفردية / الدلتا** | `ApplyLifecycleRules` **تنفّذ مباشرةً** | `OnExport` **فقط** |
| **زر «معالجة الكل»** | نفس مسار المزامنة الكاملة | `OnExport` + `OnImport` |

> **⚠️ فخّ:** «توحيد المسارين» بتحميل `OnImport` في التصدير الفردي **يُكرّر كل نقل وكل تعديل مجموعات**. يحميه اختبار `FullPipeline_MovesTheAccountExactlyOnce`.

## 4. بصمتان منفصلتان — أكثر ما يُربك تشغيلياً

| ما تريد تطبيقه | ما تُفرّغه |
|---|---|
| **سمات AD** (`l`, `extensionAttribute6`, …) | `SyncStates.CurrentHash = ''` |
| **قواعد دورة الحياة** (نقل OU، مجموعات) | `MetaverseEntries.NeedsRuleEval = 1` |
| **إعادة التصدير** (بعد تغيّر حالة سابق) | `MetaverseEntries.LastExportDate = NULL` |

**تفريغ البصمات وحده لا يُشغّل دورة الحياة إطلاقاً** — الشرط في `SyncEngine` يقارن حقول `MetaverseEntries` لا `SyncStates`.

> **⚠️ درس مؤلم:** سكربت الاسترجاع كُتب بـ `BEGIN TRANSACTION` بلا `COMMIT` عمداً (للمراجعة). تركُ النافذة مفتوحة **شلّ المزامنة بأقفال `LCK_M_IX`** لثلاث دقائق حتى انتهت المهلة — وبدا الأمر كأنه بطء في SQL. المعاملة المفتوحة لا تنتهي بمرور الوقت مهما رفعتَ `SqlCommandTimeoutSeconds`.

## 6. ميزات أُضيفت

- **تعدد الجهات في الواجهات:** مُحدِّد جهة في محرك القواعد ودورة الحياة والتقارير، وعمود «الجهة» في الجداول والتصدير.
- **تصدير/استيراد الإعدادات عبر Excel** (`SettingsTransferService`): معاينة قبل التطبيق، إعادة تحقق كاملة على الخادم عند التطبيق، وورقة غائبة = قسم لا يُمسّ. لا يشمل بيانات الاتصال ولا كلمات المرور.
- **`{message_ucs2}`** لبوابات SMS التي تُعلن الترميز بنوع رسالة (RML `type=2`).
- **`{GroupRules}`** في `AddGroups` — تشتق المجموعة من قواعد المجموعات، فتُغني عن قاعدة لكل موقع.
- **`SqlCommandTimeoutSeconds`** قابل للضبط (افتراضي 180).
- **تحذير الرموز غير المغطاة:** كل رمز حالة بلا قاعدة مطابقة يُسجَّل باسمه وعدده.
- **تحقق من قيم OU:** `MoveOU`/`Reactivate`/`Deprovision` تُرفض إن لم تكن `ActionValue` مساراً.

## 7. منهج التحقق

**اختبار الطفرة على كل إصلاح حرج:** يُعكس الإصلاح عمداً، ويُتأكد أن الاختبار **يفشل**، ثم يُرجَع. الاختبار الأخضر الذي لا يستطيع أن يحمرّ لا يساوي شيئاً.

أمثلة: إزالة حارس التجريبي · إفراغ بادئات x500 المحمية · إزاحة عمود Excel · `X4` ← `X2` في UCS-2 · إعادة استثناء `Deprovisioned` · تحميل `OnImport` في التصدير الفردي.

**اختبارات ضابطة عكسية** تمنع الإصلاح من الانقلاب إلى «افعل كل شيء»:
`RealRun_DoesWrite_SyncState` · `GenuinelyDifferentValues_StillCompareUnequal` · `StatusUnchanged_DoesNotRunLifecycle` · `AnActiveIdentityWithNoMatchingRule_IsNotMoved`.

**استخدام بيانات إنتاج حقيقية** في الاختبارات: قيمة x500 الفعلية، وحمولة `AttributesJson` لخريج حقيقي، وملفات الإعدادات المُصدَّرة.

## 9. استعلامات تشغيلية

```sql
-- ما الذي ستمسّه المرحلة التالية؟
SELECT SourceStatusCode,
       COUNT(*)                                                AS Total,
       SUM(CASE WHEN LastExportDate IS NULL THEN 1 ELSE 0 END) AS NeverExported,
       SUM(CASE WHEN NeedsRuleEval = 1 THEN 1 ELSE 0 END)      AS PendingRules
FROM MetaverseEntries WHERE TenantId = 1
GROUP BY SourceStatusCode ORDER BY SourceStatusCode;

-- تطبيق سمات AD على الجميع
UPDATE SyncStates SET CurrentHash = '', LastModified = SYSUTCDATETIME() WHERE TenantId = 1;

-- تشغيل قواعد دورة الحياة (مرحلة بمرحلة، لا دفعة واحدة)
UPDATE MetaverseEntries SET NeedsRuleEval = 1, LastExportDate = NULL
WHERE TenantId = 1 AND SourceStatusCode = 7;

-- تشخيص الحجب أثناء مزامنة بطيئة
SELECT session_id, blocking_session_id, wait_type, wait_time
FROM sys.dm_exec_requests WHERE blocking_session_id <> 0 OR wait_time > 5000;

-- معاملة مفتوحة نسيتَها؟
SELECT @@TRANCOUNT;   -- في نافذة SSMS التي شغّلت فيها السكربت
```

## 10. قبل أي تشغيلة كبيرة

```
□ اسحب البناء المُصلَح — وتحقق من الـ DLL لا المصدر
□ نسخة احتياطية من AD (System State)
□ تأكد من وجود الـ OUs المستهدفة فعلياً
□ اعرف عدد أعضاء مجموعات التراخيص قبل وبعد
□ اختبر على 3–5 حسابات أولاً، وتحقق منها في AD بعينك
□ لا معاملات SQL مفتوحة
□ خارج أوقات الدوام
□ راقب أول دقائق: ارتفاع Failed = أوقف فوراً
□ إن كانت التشغيلة تمسّ أعلام كلمة المرور: افحص pwdLastSet أولاً (انظر أدناه)
```

> **⚠️ سؤال يُنسى فيُفقد الوصول:** «ما الذي يصبح **منتهياً** فور هذا التغيير؟»
> إزالة علم «كلمة المرور لا تنتهي» عن حساب كلمة مروره قديمة تجعلها منتهية **في اللحظة نفسها** — لأن الحدّ الأقصى للعمر يسري على `pwdLastSet` القديم. حدث هذا فعلاً في 2026-07-27 وفقد **1618 حساباً** الوصول.
> التغيير نفسه لم يفشل؛ **نجح ثم كشف انتهاءً كان مؤجَّلاً بالعلم**. افحص `pwdLastSet` قبل الإزالة، والعلاج في [`Reset-PwdLastSet.ps1`](Reset-PwdLastSet.ps1).
