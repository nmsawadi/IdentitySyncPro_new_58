# IdentitySyncPro — منصة إدارة الهويات المؤسسية
## تقرير المميزات التسويقي الشامل

---

## نبذة تنفيذية

**IdentitySyncPro** هي منصة متكاملة لإدارة الهويات وحقوق الوصول (IAM) تصلح **لأي جهة** — جامعة، وزارة، إمارة، شركة. تعمل المنصة بنمط Metaverse المعتمد في الأنظمة العالمية (MIM/FIM) كجسر ذكي بين قواعد البيانات المصدرية (Oracle / SQL Server) وبنية Active Directory، مما يُلغي الحاجة إلى أي تدخل يدوي في إدارة الحسابات.

> **رؤية المنصة:** حساب AD جاهز لكل منسوب فور تسجيله في نظام الجهة — تلقائياً، بأمان، وبدون أخطاء.

**مرجع إنتاجي مثبت:** تعمل المنصة في الإنتاج لدى جهة حكومية تعليمية كبرى وتزامن أكثر من **111,000 هوية** بنجاح.

## 2. القدرات المؤسسية (تحديث يوليو 2026)

### 🏢 متعدد الجهات والمصادر (Multi-Tenant)
- عدة مصادر بيانات في تثبيت واحد: **طلاب من View + موظفون من View آخر** — كل جهة بموصلاتها وقواعد ربطها ومجموعاتها ودورة حياتها وجدولتها المستقلة (مثلاً: الطلاب ليلاً والموظفون كل ساعة).
- دعم مصدرين: **Oracle** و**SQL Server**.

### 🔓 مخطط مصدر حر بالكامل (Dynamic Schema)
- **لا توجد أسماء أعمدة مكتوبة في الكود** — تُقرأ كل أعمدة الـ View بأسمائها الحقيقية كما في الأنظمة العالمية، ويُحدد فقط عمود المعرّف وعمود الحالة لكل جهة.
- شاشة ربط الحقول تجلب أعمدة الـ View الفعلية مباشرة من قاعدة البيانات.

### 🔐 حزمة الأمان والتحكم بالوصول
- تسجيل دخول إلزامي بأدوار (مدير / مشغّل / مشاهد)، بحسابات محلية مشفّرة (PBKDF2) أو **بحسابات Active Directory** مباشرة.
- قفل تلقائي بعد المحاولات الفاشلة، تغيير إجباري لكلمة المرور الأولى، حماية CSRF شاملة، لوحة المهام محمية، وتشفير كل الأسرار المخزنة (Data Protection).
- سجل تدقيق أمني لكل دخول وخروج وتغيير.

### 📲 الخدمة الذاتية لإعادة تعيين كلمة المرور (SSPR)
- **وحدة مستقلة** بقسم إدارة خاص: تفعيل، مزود رسائل خاص، وقائمة دومينات — كل دومين باتصاله وسماته.
- المنسوب يدخل **اسم المستخدم + رقم الهوية الوطنية**، فيُتحقق منهما **مباشرة من الدومين**، ويُجلب جواله من AD ويُرسل إليه رمز SMS، ثم يغيّر كلمة مروره في الدومين مع فك القفل.
- تحصينات مؤسسية: حدود معدل لكل IP وحساب، ردود موحّدة لا تكشف وجود الحسابات، استثناء إجباري لحسابات الإدارة (fail-closed)، وسجل تدقيق كامل.

## 3. المميزات الرئيسية

### 3.1 المزامنة الذكية الآلية

#### مزامنة كاملة (Full Sync)
- قراءة كامل بيانات الهويات من المصدر دفعةً واحدة
- مقارنة تلقائية مع Active Directory
- إنشاء أو تحديث الحسابات بناءً على الفروقات
- **الاستخدام:** أول تشغيل أو إعادة معايرة شاملة

#### مزامنة تغييرات (Delta Sync)
- يعالج فقط السجلات التي تغيّرت منذ آخر مزامنة
- سرعة تنفيذ تفوق الـ Full Sync بأشواط
- **الجدولة الافتراضية:** كل 30 دقيقة تلقائياً
- **الفائدة:** الطالب يحصل على حسابه خلال 30 دقيقة من قبوله

#### مزامنة فردية (Single Sync)
- تفعيل حساب طالب واحد بإدخال رقمه فقط
- نتيجة فورية (نجاح/فشل + الحقول المتغيرة)
- **مثالية لـ:** حالات الطوارئ والدعم الفوري

#### التشغيل التجريبي (Dry Run)
- محاكاة كاملة للمزامنة **بدون أي تأثير** على Active Directory
- يعرض بالتفصيل: ماذا سيُنشأ، ماذا سيُحدَّث، ماذا سيبقى
- **ضمان الأمان:** صفر مفاجآت في الإنتاج

**أهم ضمان في المنصة — لا تفاوض عليه:**

|:---|:---|
| إنشاء حسابات جديدة | ✅ مسموح |

| **تعطيل حساب AD** | ❌ **ممنوع نهائياً** |

> هذا الضمان مُدمج في قلب النظام ولا يمكن تجاوزه حتى بالخطأ.

### 2.3 ربط الحقول الديناميكي (Dynamic Attribute Mapping)

#### مرونة غير محدودة:
- **34 ربط افتراضي** جاهز يطابق معايير الجامعات السعودية
- حقل **AD Attribute مفتوح** — كتابة أي خاصية حتى المخصصة (Schema Extensions)
- دعم كامل لـ **41 خاصية AD** المعروفة من القائمة المقترحة

#### الخصائص المدعومة:
```
Core:           sAMAccountName, givenName, sn, displayName, employeeID
Email:          mail, userPrincipalName, mailNickname
Proxy:          proxyAddresses (متعددة), targetAddress
Contact:        mobile, telephoneNumber, department, title
Location:       l, co, physicalDeliveryOfficeName
Extensions:     extensionAttribute1-15 (كاملة)
Exchange:       mailNickname, targetAddress
Custom:         أي attribute مخصص
```

#### التحويلات الذكية (Smart Transforms):
| التحويل | الوصف | مثال |
|:---|:---|:---|
| Format | تنسيق البريد | `{0}@example.com` |
| Concat | دمج حقول | `{الاسم} {اسم الأب} {اللقب}` |
| Map | تحويل القيم | `1=MALE`, `2=FEMALE` |
| GetInitials | تحويل شرطي ذكي | >4 أحرف → أول حرف |
| Static | قيمة ثابتة | `Student` دائماً |
| ToUpper/ToLower | تحويل الحالة | — |

#### Attributes متعددة القيم:
يدعم النظام تلقائياً تجميع قيم متعددة لنفس الـ Attribute:
```
proxyAddresses = [
  "SMTP:12345@example.com",       ← Primary
  "smtp:12345@tenant.onmicrosoft.com"  ← Secondary
]
```

### 2.4 محرك القواعد المتقدم (Rules Engine)

#### 6 أنواع قواعد مدعومة:
| النوع | الوظيفة |
|:---|:---|
| **Join** | ربط هوية المصدر بحساب AD موجود |
| **Projection** | إنشاء هوية جديدة في قاعدة البيانات الوسيطة |
| **ImportFlow** | نقل البيانات من Oracle → Metaverse |
| **ExportFlow** | نقل البيانات من Metaverse → Active Directory |
| **Provisioning** | إنشاء حساب جديد في AD |
| **Deprovisioning** | إدارة انتهاء صلاحية الحساب (محمي بـ Safe Sync) |

#### Versioning متكامل:
- كل تعديل يُنشئ إصدار جديد تلقائياً (v1 → v2 → v3)
- مقارنة بين إصدارين والرجوع لأي إصدار سابق (Rollback)
- سجل كامل بكل التغييرات مع التوقيت والمُعدِّل

---

### 2.5 إدارة دورة حياة الهوية (Identity Lifecycle)

#### الحالات الكاملة:
```
Pending → Active → Graduated ✓
               ↘ Suspended ⚠️
               ↘ Withdrawn ↩️
```

#### 9 إجراءات تلقائية:
- SetState (تغيير الحالة)
- MoveOU (نقل OU)
- EnableAD / DisableAD
- AddGroups / RemoveGroups
- SendSMS (إشعار فوري)
- Deprovision / Reactivate

#### فترة السماح (Grace Period):
اضبط انتظاراً تلقائياً قبل تنفيذ أي إجراء:
> مثال: "إذا فُصل الطالب → انتظر 30 يوم → غيّر الحالة"
> خلال الـ 30 يوم، إذا أُعيد قبوله → لا شيء يتغير

---

### 2.6 المراقبة والصحة (Health Monitoring)

#### Circuit Breaker الذكي:
- يراقب كل اتصال (Oracle / AD / SQL Server)
- 3 فشل متتالية → يقطع الاتصال مؤقتاً (يحمي الأنظمة من الإغراق)
- استئناف تلقائي بعد 5 دقائق
- حالة مرئية: 🟢 سليم / 🟡 تحذير / 🔴 منقطع

#### Quarantine (الحجر الصحي):
- هوية تفشل 3+ مرات → تُعزل تلقائياً
- لا تؤثر على باقي العمليات
- المسؤول يراجعها ويحلّها من الواجهة

#### Dead Letter Queue:
- عمليات فشلت نهائياً تُحفظ في قائمة انتظار
- إعادة تشغيل بزر واحد (فردية أو جماعية)

#### تحديث تلقائي كل 30 ثانية بدون إعادة تحميل الصفحة.

---

### 2.7 المراقبة المباشرة (Live Monitor)

- بث مباشر عبر **SignalR** أثناء المزامنة
- شريط تقدم مرئي + عدادات فورية
- كل عملية تظهر فور إتمامها (إنشاء/تحديث/تخطي/فشل)
- **الفائدة:** المسؤول يرى ما يحدث بالضبط في الوقت الفعلي

---

### 2.8 سجل التدقيق الشامل (Audit Trail)

- كل عملية مسجّلة: الوقت + النوع + الطالب + النتيجة + التفاصيل
- **CorrelationId** لربط كل عمليات مزامنة واحدة معاً
- البحث بالاسم أو رقم الطالب أو CorrelationId
- **الامتثال:** يلبي متطلبات التدقيق الأمني المؤسسي

---

### 2.9 نظام الإشعارات (SMS Notifications)

- إرسال بيانات الدخول للطلاب الجدد تلقائياً عبر SMS
- كلمات مرور آمنة عشوائية 10 أحرف مُولَّدة تلقائياً
- قالب رسالة قابل للتخصيص
- تكامل مع أي SMS API

---

### 2.10 إدارة متعددة الجهات (Multi-Tenant)

- إدارة **عدة دوميانات AD** من واجهة واحدة
- كل جهة (Tenant) لها:
  - اتصال Oracle / قاعدة بيانات مستقل
  - دومين AD مستقل
  - ربط حقول مستقل
  - قواعد ومجموعات وOU مستقلة
- **مثالي لـ:** الجامعات ذات الفروع والمدن المتعددة

---

### 2.11 الجدولة الذكية (Hangfire Scheduler)

| المهمة | الجدول الافتراضي |
|:---|:---|
| Full Sync | يومياً الساعة 2:00 صباحاً |
| Delta Sync | كل 30 دقيقة |
| Health Check | كل 10 دقائق |
| Data Retention | أسبوعياً (أحد 3 صباحاً) |

- تعديل الجداول بدون إعادة تشغيل النظام
- لوحة Hangfire لعرض المهام وإعادة تشغيلها

---

### 2.12 إدارة البيانات (Data Retention)

تنظيف تلقائي لحفاظ على أداء قاعدة البيانات:

| نوع البيانات | الافتراضي |
|:---|:---|
| سجلات المزامنة | 90 يوم |
| سجلات التشغيل | 180 يوم |
| سجلات التدقيق | 365 يوم |
| العمليات الفاشلة | 30 يوم |
| الهويات المحجورة | 60 يوم |

> **ضمان:** لا يُحذف أي بيانات طالب أو حساب AD أبداً — فقط سجلات النظام الداخلية.
